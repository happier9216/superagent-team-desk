# 团队工作台：SuperAgent 公开演示

一个给教程和录屏使用的小项目：产品、设计和研发一起准备周五的产品演示，在同一张工作台上看负责人、截止时间、完成进度和待跟进事项。

**所有团队、事项和时间均为虚构，可公开使用。初始版本故意保留一处状态切换故障，用于演示 Agent 从 GitHub 问题单接任务、修改、检查并提交 PR 的过程。** 它不是生产任务系统，不保存数据、不连接账号，也不会发送任何团队消息。

欢迎 Fork 并修改这个模板。本例由 GitHub 账号 A 维护公开模板，账号 B Fork 出自己的副本，再由账号 B 邀请账号 A 协作；后续问题单、评论和 PR 都在账号 B 的 Fork 中进行。

## 打开网页

在项目目录启动一个本机静态预览：

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

浏览器打开 `http://127.0.0.1:8000/`。结束后在终端按 `Control + C`。网页使用脚本模块，请通过上述本机地址打开，不直接双击 HTML 文件。

## 任务 1：修复误完成其他任务的问题

1. 页面初始是 0 / 3 已完成，右侧有三项待跟进事项。
2. 只点击“演示脚本定稿”这一行的“完成”。
3. 故障表现：三项任务全部完成，右侧待跟进清单也变空。
4. 正确结果：只有“演示脚本定稿”完成，右侧保留另外两项；撤销这一项时，也只改变它自己。

可在 GitHub 新建问题单后，用账号 A 发一条新评论，将占位内容替换为账号 B 的真实用户名：

```text
@<GitHub账号B用户名> 请修复团队工作台的完成按钮。
复现：只完成“演示脚本定稿”，其他两项也一起完成，待跟进清单全部消失。
预期：只改变当前任务，其他任务保留；撤销时也只撤销当前任务。
请先复现并运行现有测试，保留测试断言，修复后再跑同一套检查。
不要改变页面设计或新增依赖。提交 PR，说明原因与验证结果，等我审核，不合并、不直接推送默认分支。
```

已有 Node.js 环境时，在项目目录运行：

```sh
node --test tests.mjs
```

初始故障版应当是 **2 项失败、1 项通过**；修好后同样 **3 项通过**。检查通过后，仍需回到 PR 分支的页面亲手点一次。不要靠删掉断言或修改预期值来通过检查。

## 任务 2：让管家生成一份待跟进简报

任务 1 产出 PR 后，先检查该分支的页面和测试，暂不合并。由账号 A 在同一份 PR 下评论并 @ 账号 B，追加下面的小功能；两个任务沿用同一工作分支，最终整份 PR 仍等用户人工审核合并。

```text
@<GitHub账号B用户名> 请继续当前 PR，给团队工作台增加“生成跟进简报”按钮。
点击后，在页面内生成一段可选择复制的中文文字，列出尚未完成事项的名称、负责人和截止时间。
已完成事项不要出现；全部完成时写“当前没有待跟进事项”。
只在本页展示，不调用外部模型或接口，不发送任何消息。保留现有页面风格、任务 1 已修复的完成和撤销行为及原有测试，不新增依赖。
请为简报内容补上有未完成事项、全部完成两种检查，沿用当前 PR 和工作分支更新，不另开 PR。最终等我人工审核合并，不自动合并、不直接推送默认分支。
```

预期示例是“整理上手反馈｜设计同学｜周五 10:00”。这一步让 Agent 在修好故障之后，再补一个对团队讨论有用的小功能。初始版本没有实现该按钮，留给 Agent 完成。

## 文件

- `index.html`：页面外观、演示数据和交互。
- `tasks.mjs`：任务状态更新函数，初始保留教学故障。
- `tests.mjs`：Node.js 自带测试，无第三方依赖。

演示项目只有静态网页。GitHub 的 fork、问题单、PR 和服务器上的 SuperAgent 运行由教程外层流程负责；本仓库不包含凭据、服务器地址或登录配置。
